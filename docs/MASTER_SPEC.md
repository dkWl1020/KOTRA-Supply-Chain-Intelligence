# KOTRA Supply Chain Intelligence — MASTER SPEC v2.0

## 0. 문서 지위 및 범위
이 문서는 2026-11-19까지 합의한 Q1–Q44의 의사결정에 기반한 **구현 목표 명세**다. 본 문서는 목표 명세이며 실제 구현 상태는 `CURRENT_STATE_AUDIT.md`를 참조한다. 업로드된 기존 프로토타입에는 소스·CSV·원문 메모·테스트가 존재하며, 이 문서의 모든 목표가 구현되었다는 뜻은 아니다. 원본 `ORIGINAL_kotra.md`의 7+1 권역, 13개 산업, 공급망 3-Hop, 4단계 EWS, 3종 보고서, 원문 근거 추적을 유지한다. 초기에는 고품질 시연용 로컬 시스템, 최종에는 KOTRA 직원과 한국 기업 관계자용 운영 플랫폼을 지향한다.

## 1. 불변 요구사항
1. 스택: Python + SQLite + Vanilla JS. 필요한 출력 라이브러리 등은 예외적으로 명시·잠금 가능.
2. 구현 순서: 실제 데이터 수집·DB → 백엔드 → 프론트엔드. AI에게는 작고 검증 가능한 단위로 작업 배정.
3. 데이터: 공개 자료를 최대한 폭넓게 수집. 수십만 레코드 수준의 확장성을 고려하되 확보량을 보장하지 않음. 최신 현황과 장기 시계열을 병행.
4. 범위: WA, OR, ID, MT, AK, 북부 CA 22카운티, Bay Area 9카운티; CA 전체는 벤치마크 전용. 13개 산업 유지.
5. 데이터 상태: verified / reported / unverified / estimated / synthetic; 근거 출처 등급 1–4와 독립적으로 관리. 원문/수집/정제 계층 분리.
6. UI: Modern Hybrid, 종합 홈 + 원본 7개 화면, 별도 관리자. 2D GeoJSON 지도·클러스터·필터, 인터랙티브 3-Hop 네트워크, 상세 드릴다운, 부드러운 전환.
7. 분석: 기업·시설·지역·산업·품목; BFS 경로 추적과 규칙 기반 초기 EWS, 최종 LLM 어댑터. 미검증 근거 포함 시 별도 경고. 대체 공급처는 초기 후보 제시, 최종 AI 추천.
8. 보고서: 초기 템플릿/편집, 최종 AI 작성. HTML/PDF/DOCX 지원. 초기 승인 생략, 운영 시 승인 워크플로우.
9. 운영: 초기 로그인 없는 loopback 전용 로컬 개발. 배포 전 인증/RBAC/보안 검증 필수. 최종 자동 정기 수집 지원.
10. 품질: 실제 데이터·출처·기능·디자인·성능·자동화 테스트 모두 필수.

## 2. 시스템 데이터 흐름
공개 데이터/파일 → 수집 매니페스트 → 원문 보존(raw) → 정제·매칭·검증(staging) → 정규화 SQLite(curated) → FTS5/집계 → Python REST → Vanilla JS 8개 화면 → 분석/보고서. AI는 분석·작성 인터페이스 뒤에 위치하며 초기 실행 경로의 필수 의존성이 아니다.

## 4. 원본과 충돌하는 지점의 결정
- 원본 '35개 테이블'은 집계 목록에서 `users_roles`가 추가 표기되어 수치 불일치. v2에서는 고정 테이블 수를 요구하지 않으며 SQL DDL을 유일한 진실 공급원으로 사용한다.
- 원본 27 CSV/102 원문/473 근거는 명세 수량이다. 업로드된 프로토타입에서 CSV 파일과 원문 메모의 존재를 확인했지만, 각 기록의 독립적인 사실성·출처 정확성은 별도 검증이 필요하다.
- 원본 15개 수집 채널은 목표 소스 카탈로그. 초기 필수 자동 API 연결이 아님.
- 원본 단일 `web/app.js`는 화면별 모듈로 분리. 메인 화면은 홈 추가로 8개.
- 원본 20 API 라우트는 기준점이며 검색·업로드·보고서 목록·관리 API 추가 허용.
- 원본 `http.server` 기반 로컬 서비스는 운영 배포를 전제로 보안성 검토·대체 필요. 표준 라이브러리 선호가 보안 요건보다 우선하지 않음.

## 5. 우선순위 및 완료 정의
P0: 실데이터 수집·무결성·검색·지도·8개 화면·분석·3종 보고서 출력·자동 테스트.
P1: 관리자 대량 업로드·이력·시각 품질·수십만 건 성능.
P2(최종 운영): AI API·정기 수집·인증/RBAC·승인 워크플로우·서버 배포.
초기 완료는 P0/P1 계약을 통과한 상태이며 P2는 인터페이스·비활성 UI·테스트 더블까지 준비한다.

## 6. 개발 진행 원칙
각 작업 시작 시 `TASKS.md` 확인 → 최소 변경 → 테스트 실행 → 결과·미해결 사항 `PROGRESS.md` 기록. 스키마 변경은 마이그레이션과 데이터 사전 동시 갱신. 보고서·분석 결과는 데이터 스냅샷, 생성 엔진 및 근거 식별자를 보존.

## 7. 미확정 사항을 처리하는 기본값
기본 언어 한국어(영문 기업명 병기), 시간 UTC 저장/화면 현지 변환, 금액 원 단위·통화·기준연도 명시, CSV UTF-8, API JSON, ID는 내부에서만 사용. 원본 소스 라이선스 확인 전 전문 재배포 금지. 북부 CA 22카운티는 프로젝트 자체 정의이며 공식 KOTRA 관할을 뜻하지 않는다.

## 공통 구현 규칙
- Python 3.11+ / SQLite(FTS5) / HTML·CSS·Vanilla JavaScript. 초기 로컬 개발, 이후 배포.
- 원본 명세는 `../ORIGINAL_kotra.md`; 이 패키지는 1~7단계 합의 사항을 반영한 개정 설계. 원본과 충돌하면 `MASTER_SPEC.md`의 결정 로그 및 본 문서의 명시적 계약 우선.
- 수집되지 않은 자료를 확보했다고 주장하지 말 것. 예시·테스트·합성 데이터는 실제 데이터와 물리적/논리적으로 구분.
- 기능 미구현 시 가짜 성공 화면을 만들지 말고 명확한 비활성 상태·오류를 제공.
- 모든 신규 데이터의 출처/수집 시각/검증 상태를 추적. 검증 불가 데이터는 탐색 가능하되 확정 사실로 표시하지 않음.
