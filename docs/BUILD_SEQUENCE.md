# 구축 순서

## 1. 기준 파일

`schemas/datasets.json`과 `data/data_dictionary.csv`에서 열 이름과 키를 읽습니다. `regions.csv`, `region_memberships.csv`, `industries.csv`, `products.csv`, `metric_definitions.csv`를 먼저 이해합니다. 파일을 합칠 때 이름 대신 ID로 연결합니다.

## 2. 자료와 근거

`sources.csv`와 `evidence.csv`를 먼저 확보합니다. 이후 기업·시설·활동, 통계·투자, 관계·운송, 위험·사건 순서로 추가합니다. 실제 적재기는 한 트랜잭션에서 참조를 지연 검사하므로 파일 순서를 수동으로 바꿀 필요가 없습니다.

## 3. DB와 검색

마이그레이션으로 테이블을 만들고 CSV를 적재합니다. 원문 근거를 검색용 JSONL과 SQLite 검색 인덱스로 변환합니다. 원문 전체가 없는 자료는 보관된 근거 발췌·요약 범위만 검색합니다.

## 4. 화면과 분석

지역·산업 필터, 기업·시설·사건 조회, 관계망과 근거 열기를 연결합니다. 같은 기업에 대한 사건을 선택하고 근거를 조회한 뒤 분석을 만듭니다. 규칙 기반 근거 정리와 외부 생성형 AI 호출은 화면과 결과에서 구분합니다.

## 5. 검토와 보고서

분석에서 보고서를 만들고 담당자가 수정·승인합니다. 승인 후 수정은 새 검토 대상으로 처리합니다. 저장한 보고서를 다시 열고 HTML로 내보냅니다. PDF는 브라우저의 인쇄 기능을 사용할 수 있습니다.

## 6. 갱신

외부 수집은 환경에서 연결이 되는 공급원부터 켭니다. 수집 실패를 사건 없음으로 표시하지 않습니다. 기존 원문·분석 버전을 남겨 과거 보고서의 근거를 다시 볼 수 있게 합니다.

## 7. 인수와 활용 검증

README의 명령으로 신규 DB 구축, 테스트, 화면 실행을 재현합니다. 실제 KOTRA 담당자의 업무 방식·검토 기준·공유 범위는 사용자 미팅 결과를 반영합니다. 이 파일 묶음만으로 사용자 미팅이나 운영 환경 배포가 완료되었다고 처리하지 않습니다.
