# 08 관리자 및 운영
## 초기 로컬
127.0.0.1 전용 서버, 인증 없음, 원격 접근 차단. 관리자에서 CSV 업로드 미리보기→스키마 검증→중복 매칭→커밋, 오류 CSV 다운로드, import 배치/원문/수정 이력 열람. 백업·복구 명령 제공.
## 최종 배포
KOTRA 직원은 담당 권한에 따라 데이터·경보·보고서 수정, 기업 사용자는 승인된 조회·분석 중심. role: viewer/company, analyst, editor, approver, admin. 서버에서 API별 RBAC 강제; UI 메뉴 숨김만으로 권한 통제 금지. 인증 세션, 비밀번호/SSO 선택, TLS, CSRF, CORS allowlist, 업로드 제한, rate limit, 감사 로그, 데이터 접근 정책 필수.
## 수집 운영
정기 스케줄러는 추후 연결. 작업 idempotent, 403/429/5xx 재시도 정책, 실패 시 기존 정상 데이터 유지, last_successful_run 및 stale 경고. 각 수집원의 허용 정책 준수. 중복 방지는 URL만이 아니라 콘텐츠 해시·엔티티 키·시점 조합 사용.
## 복구·모니터링
DB 크기, FTS 인덱스 상태, 수집 작업 성공률, 최근 갱신, raw 저장소 크기, 오류 로그, 백업 성공·복구 리허설. 데이터 삭제는 승인 및 복구 가능한 이력 필요.

## 공통 구현 규칙
- Python 3.11+ / SQLite(FTS5) / HTML·CSS·Vanilla JavaScript. 초기 로컬 개발, 이후 배포.
- 원본 명세는 `../ORIGINAL_kotra.md`; 이 패키지는 1~7단계 합의 사항을 반영한 개정 설계. 원본과 충돌하면 `MASTER_SPEC.md`의 결정 로그 및 본 문서의 명시적 계약 우선.
- 수집되지 않은 자료를 확보했다고 주장하지 말 것. 예시·테스트·합성 데이터는 실제 데이터와 물리적/논리적으로 구분.
- 기능 미구현 시 가짜 성공 화면을 만들지 말고 명확한 비활성 상태·오류를 제공.
- 모든 신규 데이터의 출처/수집 시각/검증 상태를 추적. 검증 불가 데이터는 탐색 가능하되 확정 사실로 표시하지 않음.
